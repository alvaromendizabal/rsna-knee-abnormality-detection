# Reproducibility boundary

## Goal

This repository is **semi-reproducible by design**.

It exposes enough aggregate evidence, public-safe code, tests, decision contracts, and executed notebooks for an employer or reviewer to understand how the research is conducted without publishing restricted data or competitive implementation details.

AWS/SageMaker remains the canonical research workspace.

## What is reproducible publicly

The public repository supports deterministic checks for:

- metric direction and publication contract;
- grouped-validation counts;
- retained positive/negative research decisions;
- parent reconstruction counts;
- completed audit milestones;
- anatomy-model qualification logic;
- exact parent-fallback invariants;
- privacy/publication boundaries.

The machine-readable summary lives at reports/current_frontier/results.json.

Public-safe decision helpers live under src/rsna_research/.

Tests live under tests/.

## Run the public checks

The small publication contract is standard-library only:

    python tools/check_current_frontier.py
    python scripts/verify_review_notebook.py

For the full public tests and notebook replay, use **Python 3.12** in an isolated environment outside the checkout. `requirements-review.txt` records direct dependencies; `requirements-review.lock` locks transitive dependencies and their distribution hashes for Python 3.12. Package installation requires network access once; checks and execution then require no network, credentials, MRI or weights.

    python3.12 -m venv ../rsna-public-review-env
    ../rsna-public-review-env/bin/python -m pip install --require-hashes -r requirements-review.lock
    ../rsna-public-review-env/bin/python -m pytest -q
    ../rsna-public-review-env/bin/python examples/run_public_review.py
    ../rsna-public-review-env/bin/python scripts/execute_review_notebook.py --notebook 12 --output ../rsna-review-output/12.ipynb
    ../rsna-public-review-env/bin/python scripts/execute_review_notebook.py --notebook 13 --output ../rsna-review-output/13.ipynb
    ../rsna-public-review-env/bin/python scripts/execute_review_notebook.py --notebook 14 --output ../rsna-review-output/14.ipynb

The executor uses a real Jupyter kernel, saves the result, reopens it and verifies the output. Outputs go outside the checkout. Review runs take CPU seconds after installation; they launch no AWS workload. A notebook kernel must be allowed to bind local sockets. A separately labeled `--engine ipython-inprocess` mode is available for restricted environments; it executes real cells but is not described as a Jupyter kernel run.

## Continuous integration

Both existing publication workflows remain in place. The expanded workflow additionally runs the complete public pytest suite, the synthetic demo, and real Jupyter execution of Notebooks 12–14. It uploads the executed notebooks as a short-lived review artifact. The saved-output checks validate source/input fingerprints, plotted numbers and persistent Plotly/SVG fallbacks; they reject stale or mismatched evidence even with Python optimization enabled.

The public review refresh corrected a presentation defect in the earlier Notebooks 12–14: saved charts were not generated by their source cells. Their current chart code is executable and validated. Notebook 12 now plots macro scores present in its original source instead of unsupported target-specific saved bars. Research reports, original metric values and private experiment decisions are unchanged.

Notebook 00 is a prepared private preflight template. Notebooks 01–11 are historical records with their original private data/environment assumptions, not included in the clean public replay claim.

## Public/private split

### Public
- aggregate metrics;
- validation contracts;
- milestone counts;
- public-safe helpers;
- experiment decisions;
- architecture/research narratives;
- executed aggregate notebooks;
- CI/publication gates.

### Private
- DICOM/MRI data and reports;
- study/scanner identifiers;
- row-level predictions;
- private checkpoints and weights;
- source-recovery locators;
- cloud paths and credentials;
- exact competition fusion/inference/submission code;
- resumable private runners and return bundles.

## Why private artifacts are not required for the public checks

The public layer validates **research governance and aggregate claims**, not the hidden competition implementation.

A public check should answer:

- does the published metric contract match the documented project?
- are milestone counts internally consistent?
- are negative results still represented as negative?
- is an engineering qualification being mislabeled as a model improvement?
- would a missing anatomy route preserve the parent?
- has private material leaked into the public layer?

It should not recreate restricted data or reveal proprietary/competitive implementation.

## Evidence lifecycle

Each private AWS milestone maintains immutable run evidence, unique run IDs, logs, hashes, source identities, resource telemetry, and return bundles.

Only validated aggregate evidence crosses into GitHub.

## What this repository does not claim

This public layer does **not** claim complete historical reproduction of every private artifact, an untouched labeled confirmation cohort where lineage evidence says otherwise, complete raw acquisition coverage, a new external score when none was measured, or clinical validity.

That distinction is part of the reproducibility standard rather than a limitation to hide.
